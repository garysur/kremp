Executive Summary

The theme has several clear opportunities for Core Web Vitals improvement. The largest issues are heavy JavaScript payloads, duplicate global scripts, third-party app embeds, route-wide ZIP/date logic, render-blocking CSS/fonts, and media that can be prioritized or deferred more carefully.

The first round of work should focus on changes that reduce page weight and main-thread work without changing the customer's visual experience. These are the safest and highest-return optimizations for Shopify stores.

1.5-3.0 MB Potential raw JS cleanup from duplicate/stale override bundles.
0.5-2.5s Potential LCP improvement on pages affected by heavy JS, fonts, and unprioritized hero/product images.
100-600ms Potential interaction improvement from reducing observers, polling, app widgets, and global scripts.
15-35 pts Possible Lighthouse mobile score lift after high-impact fixes, depending on live baseline and app scripts.
These are planning estimates from source-code review. Final savings should be validated on a live Shopify preview using Lighthouse, PageSpeed Insights, Shopify Web Performance reports, and Chrome DevTools Coverage.

What I Can Change

  • Remove duplicate or stale JavaScript and load only the scripts each page type actually needs.
  • Move product/cart-only ZIP, delivery-date, and checkout validation logic off global page loads.
  • Reduce third-party app impact by delaying non-critical widgets until interaction or below-the-fold visibility.
  • Prioritize the LCP image on home, product, collection, and content landing pages.
  • Trim render-blocking CSS and simplify font loading to reduce first paint delays.
  • Replace polling, broad observers, and debug logging with scoped, event-driven code.
  • Make videos, iframes, reviews, and large custom-Liquid content load later when appropriate.
  • Add repeatable testing so speed gains do not regress after theme updates.

Recommended Work Plan

This plan starts with the work most likely to improve real user experience without visual redesign.

Phase 1: High-Impact Cleanup

Best first step for measurable speed gains.

  • Fix duplicate override bundle loading.
  • Remove duplicate jQuery.
  • Gate ZIP/date logic by page type.
  • Remove polling and debug logs.

Expected result: Largest reduction in JavaScript weight and main-thread work.

Phase 2: LCP and Render Path

Targets the first visible page experience.

  • Prioritize hero and product images.
  • Trim render-blocking CSS.
  • Simplify font loading.
  • Delay non-critical styles/scripts.

Expected result: Faster LCP/FCP and cleaner visual loading.

Phase 3: Apps and Media

Polishes pages with heavier features.

  • Delay review widgets in grids.
  • Lazy-load YouTube and video sections.
  • Defer large custom content blocks.
  • Add repeatable testing reports.

Expected result: Better INP and fewer regressions over time.

Current Findings Behind the Estimate

Very large local JavaScript Three override files are each about 1.5 MB raw. This is the biggest local payload opportunity.
Global script bloat layout/theme.liquid includes many inline scripts, page-wide handlers, and product/cart logic on routes that may not need them.
Duplicate third-party requests The layout includes duplicated rlets capture scripts and two jQuery versions. App embeds also need priority review.
LCP images can be improved The shared image snippet is good groundwork, but it lacks a high-priority setting for first hero/product images.
Render-blocking CSS/fonts Global CSS and mixed font loading can delay first paint, especially on mobile networks.
Grid pages can be lighter Product cards include review widget markup that can multiply cost on collection/search pages.

Lighthouse and PageSpeed scores vary by network, device emulation, Shopify app behavior, and third-party service response time. The most reliable success measurement is before/after testing on the same live preview URLs.

  4. Apply Phase 2 changes and retest again.
  5. Apply Phase 3 changes where useful and produce a before/after summary for the account team.
